**版本**：v1.1（本阶段已上线）
**日期**：2026-10-20
**适用范围**：工程部「发布产品标准」——产品生产标准的录入、审核发布、全员只读查阅、变更留痕、企微提醒

## 当前交付状态

生产环境已于2026-10-20发布运行代码 `3331c9e`，页面为 https://teao.work/product-standards 。本阶段停止新增功能，转入日常维护。文档收尾提交不改变线上运行代码，不重复部署。

- 标准包含7个产品分类。智能卫浴的盖、座为独立产品，不使用金蝶匹配；按产品部位归组。其他分类按各自规格模板展示。
- 管理员可直接保存发布；普通人员需有 `engineering_submit` 权限，保存草稿后选择另一位已激活用户审核。客户名和产品型号必填。
- 待审内容可由提交人撤回为草稿。本人草稿可放弃修改或删除；有生效版本时恢复显示已发布版本，首次新增草稿则从正常列表移除，均保留归档。管理员可介入驳回、删除待审和清理草稿。
- 直接停用仅限管理员或独立的 `engineering_retire` 权限，`engineering_review` 不包含停用权限。有提交权限的其他人员可申请停用，选择一位管理员或有直接停用权限的人员审核；申请批准前标准继续生效。有修订稿须先处理，停用原因必填。
- “正式标准”标签仅用于已发布、可使用的正式性质标准；草稿、待审、停用、删除和历史归档不显示该标签。顶部区分标准总数与当前筛选数，总数跨分类、遵守可见权限，排除停用和删除归档。
- 全部变更、历史版本和原始Excel批注通过“变更历史”入口查看；详情保留当前参数和待审变更对比。常规测试标准直接显示，只有冬季标准显示冬季图标和文字。
- Excel导出包含全规格属性及批注；打印隐藏审核流程信息，可打印或保存PDF，支持全部或勾选产品。
- 提交通知写明提交人与指定审核人；发布时向群发送完整属性表格并@所有人。正式和测试环境已使用用户指定的新机器人；真实URL只存放私有运行配置，不写入仓库。
- 自动催审按生产日报的工作日规则在北京时间08:00每日一次：默认周六工作、周日休息，配置休息/补班日可覆盖。启动不补发，按审核人及日期持久去重；排队与限流后再次检查，超过当天8点时段取消，防止夜间推送。手动催审保留五分钟冷却。
- 页面不提供初始化导入入口；管理员后台导入能力保留用于受控维护。本阶段收尾不重新导入Excel，不同步本地数据库。

发布及数据保护记录见 [正式发布记录](audits/release-20261020-3331c9e.md)，本阶段收尾结果见 [阶段收尾记录](specs/2026-10-20-product-standard-phase-closure.md)。群消息实际呈现和定时提醒由用户在日常业务中观察；原始Excel及资料由用户自行管理。

## 一、功能总览

工程部发布各产品（阻尼器/同步器）的生产标准，审核通过后**全员只读可查**。核心能力：

- 7 个产品分类，每个分类有**不同的规格字段（列头）**
- 标准走「草稿 → 待审核 → 已发布 / 驳回」审核流，全流程留痕
- 支持管理员后台 Excel 导入维护（预览校验、自动备份后发布；页面入口已移除）
- 提交审核 / 审核结果推送企业微信提醒
- 右上角**通用通知栏**聚合待审核等内容（可扩展）

## 三、数据模型

存储：SQLite（`data/standards.db`，better-sqlite3，WAL 模式）。

### 3.1 表结构

| 表 | 用途 | 关键字段 |
|----|------|----------|
| `standard_categories` | 分类 + 字段模板 | `key`, `name`, `fields`(JSON), `sort` |
| `product_standards` | 标准主表 | `id`(UUID), `serial_no`(**不唯一**), `category_key` |
| `product_standard_versions` | 版本表（每次编辑生成新版本） | `standard_id`, `version_no`, `revision`, `status`, `fields`(JSON), 用户 ID 与姓名快照、独立提交人 |
| `product_standard_changes` | 变更留痕 | `standard_id`, `field_label`, `description`, `author`, `changed_at`, `seq` |

> 一条标准 = 1 条 `product_standards` + 多条 `product_standard_versions`（版本历史）。
> `serial_no`（序号）**不唯一**：同一序号的阻尼器可能用于不同客户，靠「序号 + 客户」区分。

### 3.2 产品分类（7 个，字段各不同）

| key | 名称 | 规格字段 |
|-----|------|----------|
| `gear_damper` | 齿形阻尼器 | 扭矩标准 · 测试标准gf.cm · 打点颜色/喷码 · 齿轮规格 · 备注 |
| `barrel_damper` | 筒型阻尼器 | 扭矩标准 · 测试范围 · 打点颜色/喷码 · 筋条是否归位 · 备注 |
| `rack_damper` | 齿条阻尼器 | 扭矩标准 · 测试范围 · 打码 · 扭矩方向 · 装锁方向 · 备注 |
| `lock_sync` | 锁类·同步器 | 扭矩标准 · 测试标准 · 打点颜色 · 弹簧 · 备注 |
| `air_pull_cord` | 空气拉绳阻尼器 | 扭矩标准 · 测试范围 · 喷码 · 扣件 · 下座 · 轴芯 · 弹簧 · 拉绳 · 备注（9 个） |
| `air_pull_handle` | 空气拉柄阻尼器 | 扭矩标准 · 测试范围 · 喷码 · 物料 · 备注 |
| `sanitary_damper` | 智能卫浴 | 客户型号 · 产品部位 · 产品标准 · 实际扭矩 · 油号 · 下落时间 · 台阶 · 长度 · 印字 · 备注 |

> 字段模板在 `server/services/standard-store.js` 的 `CATEGORY_SEED` 中定义，`sort` 即页签展示顺序。

### 3.3 状态机

```
draft(草稿) ──提交审核──▶ pending_review(待审核)
                              │
              ┌──审核通过─────┤
              ▼               ▼ 驳回
        published(已发布)   draft(草稿)
        （旧 published → archived 已归档）
```

- `standardType`（标准性质）：`formal` 正式标准 / `temporary` 临时标准 / `new_pending` 新增待定
- 工程人员列表取「工作版本（draft/pending_review）优先，否则已发布版本」；普通用户始终读取当前已发布版本，修订期间旧版继续可查

## 四、权限模型

| 权限 | 含义 | 能做什么 |
|------|------|----------|
| `engineering_submit` | 产品标准提交审核 | 新增 / 编辑草稿 / 提交审核 |
| `engineering_review` | 旧未指定流程审核 | 审核通过 / 驳回（**不能审核自己提交的**） |
| `engineering_retire` | 直接停用产品标准 | 直接停用；可被指定为停用申请审核人（**不能自审**） |
| `admin` | 管理员 | 拥有全部权限，含初始化导入 |

- 普通用户（无上述权限）：**只读**，且仅能看到 `published` / `archived` 版本（`visibleVersions` 过滤）。
- 权限分配在「用户管理」页的页面内操作分组中由管理员配置，提交、旧流程审核和直接停用独立授权；后端按当前权限校验，撤权后立即生效。
- 新提交选择一位已激活用户作为审核人，排除提交人自己；该用户仅获得该条标准的查看和审核权限。旧未指定记录使用管理员或 engineering_review 权限。

## 八、导入机制

- 前端解析函数 `parseStandardImportRows` 已就绪，后端 `preview` / `confirm` 接口已就绪。
- 管理员页面提供「初始化导入」入口：选取 Excel → 查看错误/作废标记警告及预览 → 确认发布。
- 导入幂等键 = **序号 + 客户身份 + 型号 + 项目**（基于 `version_no = 1` 去重，客户尾部拆出的项目代号及单独打点项目可识别）：
  - 同序号 + 同客户 + 同型号 + 同项目 → 跳过（返回 `skipped`）
  - 同序号 + 不同客户或不同项目 → 正常导入
- **导入的记录直接置为 `published`（已发布）**，不经过审核，导入后全员可见。
- 单次导入上限 **10000 条**。
- Excel 解析规则（参照 `客户标准参数一览表-整理版.xls`）：
  - 识别分类标题行（齿形阻尼器 / 筒型阻尼器 / 齿条阻尼器 / 锁类、同步器 / 空气拉绳阻尼器 / 空气拉柄阻尼器）
  - 数据行序号须以 `SP` 开头
  - 列顺序固定：`0序号 1客户名 2型号 3客户料号 4+规格字段`
  - 自动识别标准性质（含「临时标准」→ 临时；含「新增序号」→ 新增待定；否则正式）
  - 数值型文本去掉多余 `.0`（如料号被读成 `340038321.0`）

## 九、⚠️ 测试数据 & 真实数据导入注意事项（重要）

### 9.1 当前数据是测试数据

- `data/standards.db` 里现有的所有标准、分类、版本**都是测试数据**（如 SP0001-F 等）。
- **上线前需要清空 / 替换为真实数据**，不要把测试数据带到生产环境。
- 本次开发中已删过一条待审核测试记录，删除前已备份到 `data/standards.db.bak-2026-10-13T12-09-31-281Z`。

### 9.2 上线后导入真实数据的注意点

1. **导入前先备份** `data/standards.db`（运行中的 WAL 数据库请使用 SQLite backup API，不能仅复制主文件）。
2. **使用管理员「初始化导入」入口**；确认必须携带预览 token，绑定内容、当前数据库版本及操作者，10 分钟有效，成功后不可重复使用。
3. **导入即发布**：导入的记录会直接变成「已发布」、全员可见；如果有些真实标准还需要走审核，导入后要单独处理（或先导入再改状态）。
4. **幂等键包含「序号 + 客户 + 型号 + 项目」**：不要误以为序号唯一就删除「同序号不同客户」的记录——序号本来就不唯一。
5. **保留客户名里的 `▲` / `*` 符号**：这些是业务标记（汽车客户 / 有变更），展示层才去掉，导入时不要清洗掉。
6. **Excel 列顺序要对**：分类标题行 + `SP` 开头的序号行，规格字段列要和模板一致（见第八节）。
7. **分类名称以系统为准**：系统内是「齿形阻尼器 / 筒型阻尼器 / 齿条阻尼器 / 锁类·同步器 / 空气拉绳阻尼器 / 空气拉柄阻尼器」；Excel 里「锁类、同步器」会被自动映射到 `lock_sync`，但其他名称务必与系统一致，否则分类识别失败。
8. **企微提醒依赖配置**：要收到提交/审核提醒，需要 `server/production-config.json` 里配置 `wecomWebhook`，且相关用户在「用户管理」里填了「企业微信账号」（`wecomUserid`）。未配置时静默跳过，不影响主流程。
9. **单次 ≤ 10000 条**，超出需分批。

## 十一、2026-10-13 评审修复

- 普通用户修订期间继续读取旧发布版；版本关联的变更记录仅对有权查看该版本的用户可见。
- 旧变更记录没有版本关联，无法可靠判断是否来自未发布草稿，因此仍供工程人员查看，不向只读用户暴露。
- 编辑/提交/审核必须携带 `versionId` + `revision`；不一致返回 409，需刷新后重新确认。
- 每次操作按最新账号权限鉴权，撤权立即生效。以用户 ID 判断自审，创建人、编辑人、提交人分开保存。旧待审记录缺少 ID 时要求工程人员重新提交；不凭姓名放行。
- 驳回必填意见、审核结果必须为布尔值（后端验证）；审核对比发布版与工作版本；历史支持完整参数展开。
- 草稿编辑继续使用同一版本并增加 revision；已发布版修订创建下一版本。每次字段变更均留痕。
- 新增装锁方向与附加说明；多行临时标记、合并客户单元格及非模板说明在导入时保留。作废标记需要管理员核查后明确确认。
