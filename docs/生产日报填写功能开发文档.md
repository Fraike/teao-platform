# 生产日报填写功能 — 开发文档（SPEC）

**版本**：v1.0
**日期**：2026-07-23
**适用范围**：装配部 + 注塑部生产日报录入、汇总、留痕与回溯

---

## 一、总览

将现有「维格表录入 → API 拉取 → 展示」的被动模式，改为「系统内直接录入 → 本地存储 → 汇总 → 展示/推送」的闭环模式。

核心特性：
- 产品从金蝶商品资料选择，人员从员工档案选择
- 按天/按产线(机台)分组展示，支持每日数据汇总
- 所有数据操作留痕（增删改），支持历史回溯
- 适配万行级数据量，虚拟滚动 + 分页双管齐下
- 保留原有企微推送能力，兼容维格表作为可选数据源

## 二、数据模型

### 2.1 装配部日报记录

```typescript
interface AssemblyRecord {
  id: string;                    // 全局唯一 ID (uuid)
  date: string;                  // 生产日期 YYYY-MM-DD

  materialId: string;            // 关联商品编码（金蝶 number）
  materialName: string;          // 关联商品名称（冗余存储）
  batchNo: string;               // 生产批号

  // 数量
  planQty: number;               // 计划生产数量
  actualQty: number;             // 当天生产数量
  accumulatedQty: number;        // 实际生产数量（累计生产）—— 自动计算或手动
  orderQty: number;              // 订单数量
  backorder: number;             // 订单累计欠数

  // 质量
  defects: number;               // 不良数
  qualifiedRate: number;         // 合格率（自动计算）
  ppm: number;                   // PPM（自动计算）
  achievementRate: number;       // 计划达成率（自动计算）

  // 工序人员（每个工序可关联多名员工）
  processes: {
    youZhu: string[];            // 注油 — 员工ID列表
    zhuangJiaoQuan: string[];    // 装胶圈

  // 时间
  workHours: number;             // 当天工作时间（小时）
  workTimeStr: string;           // 工作时间描述（如"8小时"、"10小时"）

  // 原材料批号（长文本，支持多行）
  rawMaterialBatch: string;

  // 审计字段
```

### 2.3 数据留痕（Audit Log）

```typescript
interface AuditLog {
  id: string;                    // 日志ID
  targetType: "assembly" | "injection";  // 操作对象类型
  targetId: string;              // 被操作记录ID
  date: string;                  // 所属日期 YYYY-MM-DD
  action: "create" | "update" | "delete";
  userId: string;                // 操作人ID
  userName: string;              // 操作人姓名
  timestamp: string;             // 操作时间 ISO 8601
  changes: AuditChange[];        // 变更明细
  snapshot: unknown;             // 操作前/后的完整快照（delete 时存前快照）
}

interface AuditChange {
  field: string;                 // 字段名
  oldValue: unknown;             // 旧值（create 时为 null）
  newValue: unknown;             // 新值（delete 时为 null）
}
```

## 三、文件存储结构

后端继续使用 JSON 文件存储，无需引入数据库。

```
data/
├── production-reports/          # 现有：汇总日报（保留兼容）
│   └── YYYY-MM-DD.json
├── production-records/          # 新增：原始记录
│   ├── assembly/
│   │   └── YYYY-MM-DD.json      # AssemblyRecord[]
│   └── injection/
│       └── YYYY-MM-DD.json      # InjectionRecord[]
├── production-audit/            # 新增：操作留痕
│   └── YYYY-MM-DD.json          # AuditLog[]（按日期分片）
├── production-summaries/        # 新增：每日汇总缓存
│   └── YYYY-MM-DD.json          # { assembly: DailySummary, injection: DailySummary }
├── employees.json               # 现有：员工数据
└── users.json                   # 现有：用户数据
```

> **分片策略**：按日期分片存储，避免单文件过大。每个日期最多几百条记录，单文件控制在 1MB 以内，万行级分散到 30+ 天，无性能问题。

| 策略 | 实现方式 |
|------|----------|
| 按天分片 | 前端只加载选定日期的记录，默认不加载其他日期 |
| 虚拟滚动 | Table 设置 `scroll={{ y: 600 }}`，AntD Table 内置虚拟滚动 |
| 分页加载 | 单天记录超过 200 条时，分页加载（pageSize: 50/100/200）|
| 前端缓存 | 日期切换时，已加载的日期数据保留在 Zustand，不重复请求 |
| 懒加载汇总 | 汇总数据独立接口，不随记录列表一起加载 |
| 增量保存 | 单条记录改动即时保存，不等待整表提交 |

## 六、数据留痕实现

### 6.1 自动触发点

后端在每个写操作（POST/PUT/DELETE）后自动写入审计日志：

```
POST /api/production/records/assembly
  → 写入记录 → 写入 AuditLog (action: create, snapshot: null)

PUT /api/production/records/assembly/:id
  → 读取旧记录 → 更新 → 写入 AuditLog (action: update, changes: 差异, snapshot: 旧记录)

DELETE /api/production/records/assembly/:id
  → 读取旧记录 → 删除 → 写入 AuditLog (action: delete, snapshot: 旧记录)
```

### 6.2 差异计算

```javascript
function diffChanges(oldObj, newObj, fields) {
  const changes = [];
  for (const field of fields) {
    const oldVal = oldObj[field];
    const newVal = newObj[field];
    if (JSON.stringify(oldVal) !== JSON.stringify(newVal)) {
      changes.push({ field, oldValue: oldVal, newValue: newVal });
    }
  }
  return changes;
}
```

### 6.3 回溯功能

1. **记录详情页** → 点击「变更历史」→ 展示该记录全部 AuditLog
2. 每条日志展示：时间、操作人、变更字段（old → new）
3. 可选「恢复到此版本」：将记录重置为某次 update 前的快照
4. delete 操作可「撤销删除」：用快照重建记录

## 七、自动计算逻辑

### 7.1 装配部

| 字段 | 公式 |
|------|------|
| 达成率 | `actualQty / planQty`（planQty > 0） |
| 合格率 | `actualQty / (actualQty + defects)`（总量 > 0） |
| PPM | `defects / (actualQty + defects) * 1,000,000` |
| 累计产量 | 用户填写或自动累加（同批号跨天） |

### 7.2 注塑部

| 字段 | 公式 |
|------|------|
| 合格率 | `actualQty / (actualQty + defects)` |
| 累计产量 | 用户填写或自动累加 |

## 十、关键决策

| 问题 | 决策 | 理由 |
|------|------|------|
| 数据库选型 | 继续 JSON 文件 | 项目已有 JSON 存储体系，无需引入 SQLite |
| 分片策略 | 按日期分片 | 每日几百条，文件大小可控，查询简单 |
| 实时保存 | 行级即时保存 | 用户体验好，避免整表丢失；配合乐观锁防冲突 |
| 审计快照 | 存储完整记录副本 | 回溯简单直接，文件存储空间成本低 |
| 累计产量 | 用户填写 + 提示 | 跨天自动累加逻辑复杂（批号匹配），建议辅助计算 |
| 产线/机台 | 用户可新建常用值 | 维格表中产线名不固定，允许用户维护常用列表 |
