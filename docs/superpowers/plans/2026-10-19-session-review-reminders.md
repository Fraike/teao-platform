# 登录有效期与待审提醒实现方案

用户已确认固定15天免登录、取消12小时限制，以及全天每两小时群提醒；本次一并排查 Chrome 密码保存。

## 规则

- 服务端签名登录开始时间与固定到期时间；前端以签名期限为准。续签不延长到期时间，活动不顺延。停用、密码重置和主动退出仍失效。
- 未勾选免登录时令牌仅存当前标签页 sessionStorage，刷新保留；勾选时存 localStorage。服务端均有15天有效期上限，不再检查12小时。
- 待审提交后仍立即通知，后台每分钟检查，从提交或上次提醒满两小时起定向提醒审核人；合并同一审核人的到期事项。只处理当前有效待审版本，排除提交人自己与停用用户。
- 持久化每个待审版本、提交批次的提醒时间，发送前原子占用，重启不重复补发；恢复运行最多补一次，不重放全部错过时段。外部发送存在超时不确定性，失败后两小时再尝试，不立即重发。
- 未配置群机器人不消耗提醒期限。群消息失败、未绑定企微账号时如实处理，不使用 @所有人代替定向提醒。
- 登录表单已有正确 autocomplete 标记；增加明确表单名、提交语义、可访问字段名，保留成功后跳转、失败留在原表单。不得在应用中保存明文密码，浏览器原生保存提示受 Chrome 设置约束。

## 任务

1. authSession/api/authStore/users 实现固定期限和存储方式，覆盖12小时、15天边界、续签、旧令牌、退出竞态与密码重置。
2. 新增 standard-review-reminders 服务：SQLite 状态、分组发送、每分钟 cron、启动检查；假时钟与假发送器覆盖时间边界、重启、失败、审核完成、重新提交和并发。
3. LoginPage 表单语义和输入识别检查；浏览器验证自动填充值提交，不宣称强制触发 Chrome 保存弹框。
4. 执行关联测试、完整测试、Lint、构建；不提交、不部署、不向真实企业微信群发送测试消息。本地后台不自动重启，以免旧待审任务触发通知。
