## 本轮发现的新增导入缺口（必须先修复）

1. 主表当前仅补合并客户名；型号、料号、备注、归位和临时说明也存在跨行共享，须按真实合并范围展开到产品，禁止凭空向下填充。预览识别58个共享值、38个受影响产品；SP0077-B、SP0078-B的型号/料号等有明确锚点，不属于真正缺失。
2. 4处合并锚点含批注，需要把同一原始sourceCell关联所有适用产品，不重复生成来源批注。只有作者的批注不制造变更正文。
3. 31条客户文本中的项目号跨行/空格导致旧拆分失败；仅按项目匹配去除空白，不删除英文客户名中的有意义空格。原文始终保留。
4. 新主表行号因新增产品平移，不能以旧地址不匹配得出原文丢失结论。新基线按新hash/sheet/单元格归档、以完整产品身份比对。
5. 现有追加导入不能完成全量替换；须实现受控临时库构建与校验、备份/停写/换库/回滚入口。当前来源核验不等于已完成这些能力。

## 边界

- 仅替换产品标准模块数据，包括标准主记录、版本、变更历史、来源批注、导入来源、旧待审/催审状态、公告发送队列及查询版本状态。
- 原标准数据从正式在线库移出，但先做可恢复归档，不直接删除；不能清空整个data目录。账号、角色权限、密码找回、生产日报、报价、金蝶缓存、员工、反馈及企微配置保持独立。
- 新Excel是经过管理员核定后的正式基线。首次导入记为“上线基线初始化”，不伪造提交/审核人员或日期；源文件存在临时、待定、作废标记时逐项确认，不默认发布全部行。初始化不逐条群发，不生成旧审批任务。
- 不再按旧70套卫浴保留在线历史的方案执行；旧记录仅在归档中追溯。旧卫浴脚本只接受旧文件hash/45产品/50批注，不适用新版全量基线；保留文件不执行。

## 已确认的实现缺口

1. 当前confirmStandardImport为追加/跳过已有业务身份，不是replace；不能通过再次点“初始化导入”完成清空替换。
2. 当前parseStandardImportFile每次只选第一个匹配的常规/卫浴工作表；新版若按分类分多个sheet，需明确逐sheet映射、完整覆盖和未处理sheet报告。
3. 新版来源hash不同，不能套用旧文件的作废行决定、空型号补齐或固定数量断言；需为新文件建立明确的来源/异常决定。
4. 查询版本仅是数据库内revision；换库时必须确保新revision严格大于停服后旧库revision，避免客户端看到相同版本继续保留旧数据。重启服务清空服务端列表缓存，并要求用户刷新页面。

## 实施流程

1. 接收原始Excel，计算SHA256、枚举全部sheet/分类；原件只读保存。记录数据截止时间，正式切换前暂停标准修改或重新生成差异。
2. 独立解析全部规格、内部换行、齿轮多规格及原始批注，检查合并单元格和来源行。智能卫浴按盖/座独立产品，不错误补充项目代号、客户料号。同序号不同客户/型号/项目不能按序号直接去重。
3. 预览报告：各分类产品数、状态数、缺失/冲突/重复、唯一原批注数与产品批注关联数分别统计；列出当前库独有、新Excel独有、字段变化及最近新增标准。未收进Excel的真实新标准不能默默遗漏；与用户确认最终来源口径。
4. 在独立临时路径新建标准库，沿用已审核的分类模板与当前schema导入，仅生成初始化历史和来源。旧审核历史、旧催审、旧outbox不带入。需实现专用受控基线入口，普通追加导入接口不增加日常“清空库”按钮。
5. 校验临时库完整性、外键、每分类数量、业务身份、每条字段及批注；反向Excel导出复核、关键规格打印复核；测试幂等/失败回滚/取消/旧待审不出现/初始化不群发。
6. 生成不可变预览清单和fingerprint，绑定新Excel hash、解析结果hash、schema版本、目标库及旧库状态；执行前再次核验，若期间新增/修改则拒绝继续，重新预览。
7. 获得对应的正式数据替换确认后，进入维护窗口并停API与其他写入者；使用SQLite一致性备份归档旧标准库。先验证新库，再将旧standards.db及其WAL/SHM作为同一运行集移出，关闭/检查点完成后原子放入新库；不向仍运行的SQLite连接覆盖.db，不把旧WAL留在新库旁。
8. 重启、健康检查、登录权限、各分类/批注/导出/打印/通知角标验收；开放前失败可恢复完整旧库。开放后已产生的新业务数据不能因回滚直接被旧快照覆盖，须独立评估。
9. 定时催审先关闭，确认正式群、人员绑定和正式待审任务后再启用。群内旧消息无法随数据库清理撤回；如需说明正式切换基线，应另行确认发布一条切换公告，不自动群发全部标准。

- 新基线替换工具及本地演练已通过；正式环境维护、进程停写与来源指纹仍须现场核验。
