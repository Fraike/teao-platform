# 产品标准临时校对模式

管理员独立开启临时校对模式，默认关闭，授予engineering_maintain且依赖engineering_submit。仅激活普通用户在模式开启时可免审核修改已有发布标准；管理员原权限不变。新增、复制新增仍正常审核。

已发布或本人修订草稿可校对保存；他人草稿、待审、停用、删除不可借此绕过流程。保存创建/更新修订版本并立即发布，旧版本归档，修改人/差异/历史保留，明确“校对更新 · 免审核”，不伪造审核人、不产生公告或提醒，不改变其他推送开关。旧版本残留公告终止发送。

提交带maintenance=true明确本次意图；服务端事务内复核模式、权限、版本和所有权。模式或授权变化使旧页面请求失效，返回权限/冲突而非误报生效。列表能力与集合版本检查包含配置版本，切换账号清空旧能力。

设置与权限配置、标准保存流程、页面提示按钮分步实现；隔离数据库模拟验证所有分支、并发冲突、版本和输出，相关测试/Lint/构建。只本地修改，不提交部署、不发真实通知。

## 验证结果（2026-11-09）

已接入系统设置和权限管理，默认关闭。打开列表或详情中的编辑入口时，沿用详情请求刷新实时权限，不额外重拉整个列表；旧客户端的校对请求仍由服务端拒绝越权。复审发现的标签页缓存问题已修复。

完整npm test通过；最后的声明顺序修正后，5项前端定向测试、Lint、构建和差异检查通过。缺失私有Excel实源的既有测试按原规则跳过。未提交、部署或发送真实消息。

## 授权入口和设置页操作整合

免审核授权从用户权限面板移到“系统设置 → 产品标准临时校对模式”。管理员可搜索、多选已激活且有提交权限的普通用户；沿用原engineering_maintain权限，已有授权保留。专用名单接口检查管理员、候选资格与名单版本，旧用户权限接口不再接受该项。

页顶统一“刷新设置”和“保存设置”，显示未保存状态，只写已修改项。关闭模式优先保存，开启时先保存人员；各项校验各自版本，部分保存失败明确说明哪些已保存。产品标准模块、页面交互、Lint、构建及diff检查通过，未提交部署。

上线复盘补充：启用模式须同时校验模式版本和人员名单版本。保存名单并启用时，使用名单保存响应中的新版本；旧页面或缺少名单版本的启用请求返回409，模式保持关闭。关闭模式不受名单冲突影响。接口、页面交互、Lint、构建验证通过。
