# 恢复图纸批量导入协作接口

用户已确认：纵向 PDF 由用户自行处理为横向；批量导入接口可以重新开放。本轮只实施此范围，不自动旋转或改写原 PDF，不执行线上部署和数据导入。

1. 恢复批次创建、PDF 扫描和确认导入三个 POST 接口；沿用既有批次查询与预览接口。
2. 所有写入接口先登录校验，再校验管理员或 product_drawing_manage 权限；产线普通账号不能调用。扫描使用 25MiB 二进制请求上限，不建立不受控公开上传地址。
3. 扫描只保存预览及候选；确认时必须明确料号、图号、版本、客户范围和结构，沿用确认后直接发布、哈希去重、部分失败重试及幂等规则。
4. 保留 PDF-only 和每页横向校验。纵向文件可扫描预览，确认发布仍会被拒绝；用户修正后创建新批次重新扫描，不自动扩大客户范围。已成功扫描的同批次/同路径不能用不同内容覆盖，服务会明确提示创建新批次。
5. 本轮仅重新开放后端接口，商品列表的批量导入 UI 入口继续关闭；不升级依赖或处理其他上线阻断，后续另行确认。

验证：先更新真实 HTTP 路由测试并观察失败，再恢复路由；覆盖匿名/普通账号拒绝、管理员及工程权限、扫描不发布、确认发布、重复执行、纵向拒绝及权限撤回；执行商品回归、lint、前后端类型检查、构建和独立复查。

Ruling: 复用现有 codex/product-drawing-management 分支和服务层，不创建新工作树；不提交、推送、部署、重启、改线上或本地业务数据。原“关闭批量写接口”的决定被本轮用户明确指令替代，仅适用于这里列出的接口。
