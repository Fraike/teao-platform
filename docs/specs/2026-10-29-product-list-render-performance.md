# 商品资料打开性能优化

用户已确认按前次排查方向优化。目标是减少隐藏产品标准大表格对商品资料页面的影响，不以减少可用数据或新增分页换取性能。

## 范围

1. 已加载行数或服务端标准总数达到 100 时，使用现有 Ant Design 虚拟表格；启用后在该标签会话内保持，避免筛选变少时替换表格子树、影响输入焦点。初次带筛选进入时也可按总数预判。始终为小数据集的会话维持普通表格。完整筛选、统计、打印与导出仍读取全部数据。
2. 行高由表格测量，支持多行齿轮规格和测试标准，不截断业务内容。复用同一行选择逻辑，虚拟行保持按标准 ID 高亮、键盘操作与内部料号链接。
3. 共享表格滚动适配支持虚拟表格：记录可见标准 ID 与偏移、纵向位置及横向位置。冷恢复先按 ID 找回记录，再校正偏移；目标消失则恢复最接近的有效位置。
4. 虚拟表格拥有自身滚动恢复，避免全局 DOM 路径恢复和虚拟滚动同时修改位置。隐藏页继续暂停测量和业务刷新。

## 验证

- 346 条标准实际挂载行数受可视区域控制；全部数据仍可搜索和滚动访问。
- 点击内部料号后热返回、超过 5 页后的冷返回，保留位置、横向滚动和高亮。
- 多行内容、固定列、分类与组合筛选、记录删除、普通列表、打印导出回归。
- 在本地浏览器对比节点规模和切换表现，完成相关测试、全量测试、lint、类型检查和构建。

只改代码；不提交、推送、部署或重启现有服务。不变更业务数据、权限或图纸文件。

## 验证结果（2026-10-29）

- 真实本地数据：当前齿轮分类 346 条，首次稳定视图约挂载 16 行、1205 个节点；优化前同类页面 23336 个节点，减少约 95%。全部记录仍保留在数据集中，无分页。
- 真实鼠标点击中部内部料号并返回：纵向 7202、横向 992、来源行偏移 463 与蓝色高亮保持；窗口变宽时横向位置按新的滚动边界限制。
- 严格等待标准页被 5 个其他业务页挤出并从 DOM 移除后再返回：纵向 7277、横向 840、来源行偏移 488 与高亮完全恢复。修复 StrictMode 首次效果重放中断恢复的问题。
- 筛选 346→3→346：过滤输入框和焦点保持。对照加载器禁用模式保持后可复现输入框卸载；当前实现通过回归。
- 快速切换普通/虚拟表格后继续滚动：快照继续更新；修复恢复保护标记未释放的竞态。
- 打开商品资料时，5 个保留页合计约 2304 个节点，隐藏标准表约 509 个节点（按当时视口窗口变化）。本次不宣称没有实测的延迟或内存百分比。
- 全量 `npm test` 通过，缓存专项 49 项通过；lint、应用和商品服务类型检查、构建、`git diff --check` 通过。现有测试环境有 React act/组件弃用提示，构建有既有包体积提醒。
- 全量服务测试使用 Node24 与现有 server SQLite 依赖对齐；仅测试进程通过临时模块解析钩子对齐 ABI，未安装或重编译依赖。前端 lint/build 正常运行。
- 独立代码复查完成；窄屏测试覆盖已恢复默认尺寸，临时诊断浏览器标签已关闭。原有服务未重启，业务数据与图纸未修改。
