# 图纸直接发布与管理操作修正

用户授权修复发布失败并简化操作；保留商品图纸管理权限，上传者确认后直接发布，无需审核，管理表格去掉原件按钮。

根因：正式issueToken不携带name，jwtAuth只补授权字段。商品路由却把payload直接当ProductActor，导致发布事件actor_name/批次created_by非空约束失败（500）。旧路由测试把姓名放进了JWT而漏报。改为从账号资料读取当前显示名，用户名/ID兜底。既有审核产品标准权限与商品图纸独立，不修改标准审核规则。

测试：JWT不包含姓名仍可创建批次/发布/停用/打印，普通用户无管理权限不能发布。DOM验证仅发布和停用，二次确认直接请求发布、不经过审核接口，失败提示在页面保留。

不直接发布用户实际图纸，不提交、推送或部署。

## 验证结果
- 先用不携带name的JWT复现created_by非空约束500；修复后批次、上传、直接发布、打印路由均通过，并断言从账号资料取得正确上传/发布人。
- test:products（含两项新DOM测试）、lint、build、前后端类型检查、diff检查通过。
- Mike明确选择不重启本地API，由其自行重启。运行中的后端尚未加载本次修复；未操作真实图纸发布或更改账号权限。
