# 审核通知精简与装配日报商品保存修复（已确认，本地实施）

## 已知需求

- 用户已有企业微信自建应用，可由管理员配置企业 ID、AgentId、应用 Secret 和可见范围。
- 待审核通知改为只向指定审核人发送应用消息，避免在群里点名；删除“查看并审核”链接行。
- 审核通过后的群通知保留版本号和完整标准参数表，去除原始批注及重复审核记录等附加信息；不能精简或截断标准参数。
- 修复装配生产日报复制历史记录、重新选择带料号商品并保存后，关闭页面再打开仍出现旧商品的问题。

## 任务一：审核人个人通知

复用已有用户的 wecomUserid 绑定，新增自建应用消息通道。企业 ID、AgentId、Secret 从服务端持久环境配置读取，不写入前端、仓库或日志；缓存 access_token，合并并发获取，明确处理过期、无可见权限、成员无绑定、发送失败和发送结果不确定。

提交待审、定时催审、手动催审及停用待审使用同一收件人路由，只发给当前有效的指定审核人。发送前复核权限、任务仍待审且审核人未变更；无绑定/未配置/发送失败须在系统中明确显示，不能显示成功，也不自动改发群里或全部审核人。旧未指定审核人的历史任务保留在系统待审列表，需明确分配后才能个人提醒。

群机器人保留用于已发布公告与日报；不把机器人 webhook 当作个人消息接口。个人消息是企业微信自建应用通知，不是冒充员工的普通聊天消息。只做模拟接口测试，不向真实成员或群发送测试消息；实际配置和联调在后续明确确认的环境中完成。

待审示例（分类、型号按实际数据）：

> 【产品标准待审核】
> 齿轮阻尼器 · SP0001-A · V2
> 客户：某客户｜型号：RD-T001-15
> 提交人：张三

催审按审核人聚合为简短列表，保留待审数量与标准身份；不再逐项重复操作指引、长 URL 和工作日提醒规则。停用待审额外保留停用原因。

## 任务二：审核通过后精简发布

按用户补充要求，新发布公告只保留版本号和完整标准参数表；删除独立的审核人、发布时间、审核意见、操作指引、原始 Excel 批注和审计记录。这些附加信息继续保留在系统。

保留完整参数表：按当前标准分类及适用变体展示全部标准参数，包括扭矩、夏季/常规测试、适用的冬季测试、齿轮规格、颜色/喷码等；保留原值、数值、单位及多行内容，空值按现有规则展示，不用关键字段白名单代替完整参数。管理员直接发布与审核通过共用模板，仅区分状态文案。发布群通知的现有接收群范围保持，不改变其他生产日报通知。

按现有各分类字段定义检查完整性，覆盖成对马桶阻尼器等变体的所有适用参数。超过企微单条消息长度限制时按参数行安全分段发送，明确版本及分段序号，保证参数完整送达；不能以“去系统查看”替代剩余参数。待审消息仍不保留“查看并审核”行。

示例：

> 【产品标准已发布】V2
>
> 下方为完整标准参数表，包含该分类/变体全部适用参数及原始数值、单位。

保留发布队列的去重、失败/不确定状态、限流及安全重试机制。仅新入队通知采用新模板，既有已入队消息保持原快照和发送进度，不在本轮自动重发或改写线上队列。

## 任务三：装配日报保存一致性

已用真实装配组件、模拟本机 HTTP 请求和隔离 SQLite 数据库复现：重选新商品后数据库字段正确，但重开表单时 Form.useWatch 默认不监听未注册的 productId/productNumber，导致同名商品退回历史显示。已为装配和注塑使用 preserve:true 监听标识；另为更换商品的更新接口增加共享的可信商品元组校验，保留历史记录不改商品时的兼容性。

实施时先用隔离数据复现：复制无商品 ID/料号的历史记录，选择新商品，保存，关闭/重新打开页面，再读取和编辑新记录；同时覆盖同名不同料号、已有旧 ID、清空重选、编辑已有记录及缓存重建。记录实际提交、响应与持久化字段，定位问题发生在表单、服务端还是页面缓存。

修复要求：商品 ID、料号、名称和规格使用同一选择结果更新，保存后重读仍一致；保留原历史记录。新建/复制必须选择有效商品；编辑旧记录不改商品时继续允许保留历史值，主动更换商品时验证当前数据及部门归属。排查并复用共享商品选择逻辑，检查注塑页是否有同类风险，避免复制一套实现；保持现有缓存和增量读取效率，不额外逐条查询金蝶。

只修代码，不自动批量修复已经保存的错误数据。若确认存在受影响旧记录，后续列出只读审计范围和修复预览，另行确认数据修复。

## 验收与操作边界

- 通知：收件人隔离、撤权/改审核人、重复触发、token 并发/过期、超时和明确失败、分段字节长度、版本号及所有分类/变体的完整参数覆盖；所有发送使用模拟接口。
- 日报：真实组件选择→保存→数据库重读→页面重开回归，覆盖装配及共享层；旧历史记录不被覆盖。
- 运行对应专项测试、全量测试、Lint、类型、构建和必要本地浏览器验证。
- 保留此前未提交的依赖升级和业务修复；直接在 main 工作，不提交、推送、部署、修改线上配置或发送真实企微消息。
