# 平台复盘后的优化

用户确认开始优化。在main仅改本地代码，不提交推送部署，不清理线上图纸、备份或原始资料。

优先处理共享报价加载hook中的脏草稿切换、异步覆盖和按账号隔离；旧无账号草稿原样保留但不自动归给新账号。商品读取按实际DB与标准变更立即失效，减少重复调和和全量构建，权限每次复验。

PDF解析失败必须释放loading task并保留原错误。发布时保留最近两个历史manifest中可验证的静态资源，不覆盖新资源；更旧页面资源不可用时提示保存草稿后刷新，不自动刷新。历史记录、两份锁及兼容迁移保留。

修正文档与运行版本、持久配置、手动发布流程；不追求一次性全站重写或升级所有依赖。先失败测试后修复，完成业务/权限/缓存/回滚、lint、类型、构建和独立复查。基准仅作为本地合成对比，不冒充线上收益。

## 本地验收结果

- `npm test` 全量通过，含产品、标准、报价及标签缓存回归；新增缓存失效、草稿切换、账号隔离、PDF 失败清理、懒加载失败与静态资源保留用例。
- `npm run lint`、`npm run build`、`npx tsc --noEmit -p tsconfig.products.json`、`git diff --check` 通过。构建仍有既有的大 chunk 提示，未为消除提示盲目拆包。
- Node 24 验证使用 server 对应的 SQLite 原生依赖；未重建共享依赖、未修改锁文件。
- 独立复查发现的新草稿取消跳转地址问题已修复并补回归；最终未发现剩余可确认的 P1/P2。
- 1323 条数据、100 次调和与查询的本地合成基准由约 202ms 降至 48ms，线上实际收益待部署后测量。
- 旧账号未归属草稿不删除、不自动迁移；旧资料、业务历史和备份不清理。全部改动仍在本地，未提交、推送、部署或重启服务。
