# 撤回审核与清理草稿

用户已确认：仅提交人撤回待审内容，保留为草稿；草稿创建人或原提交人可清理本人草稿，管理员可清理全部草稿。旧记录缺少可靠身份时仅管理员清理。不发送群通知。

POST /api/standards/:id/withdraw 和 /discard-draft 接收原界面的 versionId/revision，实时校验激活账号、身份及当前版本/状态。撤回变为 draft，清空本次指定审核人、提交时间、审核结果，保留提交人和参数；记录操作人和时间，停止原审核/催审。新审核周期生成独立、单调的提交时间，即使系统时间相同也不复用旧提醒键；从新提交时间重新计算2小时。

清理草稿复用管理员删除的归档逻辑，状态为 deleted，不物理删除。首次新增内容从正常列表移除，详情关闭；存在已发布版本时恢复已发布参数/分类/状态，“草稿／有草稿”不再出现。原已发布版本、批注、发布通知状态保持不变；归档版本号永不复用。接口返回 data 为恢复后的 StandardDetail 或 null。

列表和详情使用相同权限判断和按钮。操作直接展示，不进菜单，清理无需理由但必须确认。确认弹窗锁定打开时的版本快照，后台刷新不得悄然更换 revision；同步防重复提交。审核、重新提交、撤回、删除发生竞争时仅一方成功，其余返回冲突。

验收：隔离 HTTP + store 用例验证本人/他人/管理员/旧草稿权限、并发、恢复已发布记录及批注/通知不变、重新提交计时；前端覆盖确认、防重复、弹窗期间刷新、撤回→清理→无草稿标记、首次新增删除后关闭详情。全量测试、构建、lint 与本地服务检查完成后交付；不提交、不推送、不部署。

终审兼容修复：版本表通过可重复的启动迁移新增内部 last_submitted_at（TEXT，可空），撤回前保存旧提交时间，新提交更新此下限；升级前没有结构化提交日志的记录也能在冻结／回拨时钟时生成独立提醒周期。已补禁用账号撤回401与前端409不报成功的回归用例。

交付验证：npm test 全量通过（最后一组前端用例106/106）；生产构建、定向 ESLint、git diff --check 通过。终审提出的旧提交时间保护已修复并复核通过。本地服务已重启，API、页面及旧库新增列检查通过；未提交、未推送、未部署。
