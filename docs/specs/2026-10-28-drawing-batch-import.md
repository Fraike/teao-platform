# 成品PDF批量导入

用户已确认实施，沿用 codex/product-drawing-management；不得执行实际文件夹导入、发布、提交、推送、部署。

## 实现
1. PDF内容寻址存储：共享不可变原件，保留每料号现有图纸生命周期及权限；旧存储只读兼容，不迁移实际数据。
2. 浏览器选择目录，仅候选成品/客户/根目录PDF逐个上传到私有暂存区，记录批次、路径、哈希、提示与失败原因。子件、3D、图片、隐藏项跳过并计数。扫描为预览，不创建生产图纸。
3. 文件名提取系列，文件夹交叉验证；客户/项目只是候选线索，不自动关联。必须明确选择每个料号的通用/客户标准范围、图号、版本。
4. 确认导入为草稿，按每个料号保存检查点，支持部分失败重试；哈希和决策指纹确保幂等与防止修改已导入关系。用户以后从既有详情独立发布。
5. 批次列表、条目预览与关联确认UI，复用现有文件鉴权。所有新接口仅图纸管理员可用。

## 验证
临时目录/数据库验证T001、T010分流、V109客户候选、重复路径与重复内容、错误/恶意PDF、权限、范围冲突及部分失败重试；页面交互/API路由、全量测试、lint/build/类型检查，最终独立复查。

## 决策
- 浏览器目录选择而不是服务器任意路径扫描，兼容部署且避免暴露服务器文件系统。
- 原件按哈希单份存储，多料号以现有product_files记录关联；发布只影响该料号，不隐式发布同系列其他商品。
- 首期不批量发布、不自动猜图号或版本，不以日期判断有效性；失配项目手动选择并确认。
