# 管理员介入待审标准

用户确认的范围：管理员无需是指定审核人，即可驳回待审内容或归档删除；驳回原因必填，退回草稿并沿用提交人通知。删除原因最多2000字，界面需勾选确认；不物理删除任何参数、源批注、版本或操作记录。普通人员的指定审核人规则、通过审核规则保持原样，管理员介入驳回允许处理旧身份缺失或自己提交的待审内容。

接口：沿用 POST /api/standards/:id/review（approve=false，只有管理员绕过指定审核人及自审限制）；新增 POST /api/standards/:id/discard（versionId/revision/reason），重新读取当前角色，事务内校验当前仍待审并做逻辑归档。操作都记录实际管理员及原因，离开待审状态后自然停止手动及定时催审。

归档状态为 deleted，前端标注“已删除（归档）”。默认列表隐藏；管理员可用该状态筛选，并通过详情/历史归档入口追溯。普通用户及生产只读接口不返回归档删除的未生效内容。已有发布版本保持生效，其分类恢复；最新可操作版本排除 deleted，新修订按所有历史 MAX(version_no)+1 分配，避免复用版本号。删除首次新增内容时整条标准从默认列表消失。

列表、详情共用管理员操作弹窗。必填原因、二次确认、防重复提交、加载后版本变化及服务端版本冲突均阻止误操作。管理员新增了介入按钮，不额外获得非指定审核任务的通过权限。

验证：隔离 HTTP 路由测试覆盖越权/撤权、版本冲突、必填原因、删除保留批注、原生效版本及导出摘要、单调版本号、管理员归档历史与普通读取隔离、处理后停止催审。前端覆盖列表/详情权限、保留原审核通过限制、原因与确认、防重复和旧版拒绝。上线只部署代码，不同步或替换业务数据库；提交、推送、部署仍需另行确认。

终审补强：列表接口增加 versionId/revision 快照，管理员弹窗必须匹配界面原来的版本与修订号；同一版本驳回后修改重提也要求重新查看，不能悄然使用新 revision。删除归档筛选禁用导出/打印，保留历史参数查看入口；非管理员失去角色后自动使用普通列表筛选。

实施验证：npm test 全量通过（最后一组前端用例100/100）；生产构建、定向 ESLint、git diff --check 通过。管理员弹窗、归档页面及同版重提冲突均有回归。本地开发服务已重启并完成页面/健康检查；未提交、未推送、未部署。
