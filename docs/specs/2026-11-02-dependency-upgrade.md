# 依赖升级与开发工具漏洞修复（已确认，本地实施）

## 目标

先解决开发工具依赖审计问题，再将项目直接依赖升级至执行时 npm 官方 registry 的最新稳定版本，不使用 alpha、beta、rc。保留现有未提交业务修复，不提交、推送或部署。

## 实施任务

1. 升级 ESLint、typescript-eslint 及相关插件，重新解析锁文件，确认 minimatch 漏洞消除。优先采用上游兼容版本；如上游仍引入受影响版本，先验证 API、Node 要求及 lint 行为，再决定是否需要范围明确的 override，不使用 audit fix --force。
2. Ant Design 5.29.3 升至 6.6.8，图标包升至 6.3.4，移除 v5 React 19 补丁依赖和 import。依据官方迁移说明调整不兼容 API、内部 DOM 样式、弹层和表格交互，保留现有业务行为。
3. 更新其他前端与工具链依赖，包含 React/React DOM、Vite、TypeScript、PDF.js、Zustand 等。运行环境继续使用生产要求的 Node 24，Node 类型保持对应的最新 24.x，PDF 主程序与 worker 版本保持一致。
4. 服务端独立适配 Express 5、node-cron 4、better-sqlite3 13 等主版本变更，检查路由匹配、错误处理、定时任务、原生依赖安装和数据库兼容；两份清单与锁文件同步检查。无需更新的依赖保留，特殊分发的 SheetJS 单独核实官方版本，不能直接替换为 npm 上的旧包。
5. 全量回归：lint、类型检查、npm test、build、根目录与 server audit，以及干净安装验证。重点验证报价草稿、PDF 导出与图纸、表格筛选/虚拟滚动/滚动恢复、日期中文显示、弹窗、登录权限与日报调度。对 UI 变更进行本地浏览器检查。

## 完成标准与边界

当前已发现的兼容约束：最新 typescript-eslint 8.72.1 声明仅支持 TypeScript <6.1，而最新 TypeScript 为 7.0.2。默认保留受支持的最新 TypeScript 6.0.x，并在验收中列明原因；不通过忽略 peerDependencies 强装。最新 ESLint 10.14.0 仍依赖 minimatch ^10.2.6，单纯升级 ESLint 不能保证消除漏洞，需要专项验证修复方案。

- 无未解释的新增审计问题；目标为根目录和服务端均无已知漏洞。无法安全解决时明确记录阻碍，不隐藏报告。
- 不因追求版本号而静默降级功能、削弱测试或修改生产 Node 配置；出现无法兼容的主版本时先报告。
- 锁文件固定验收过的版本；今后优先最新稳定版，但更新仍经过兼容性检查和回归，不在安装时无条件浮动到 latest。
- 不操作生产数据、不执行资料导入、不清理本地文件；旧发布包因依赖变化必须重建，发布需另行确认。
