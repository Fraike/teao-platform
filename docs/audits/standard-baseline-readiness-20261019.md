# 产品标准上线评估：新版Excel正式基线

结论：功能代码已达到进入上线验收的阶段；尚不能直接宣告正式上线。主要剩余项是新版Excel核验、专用全量基线替换及正式环境验收。本轮仅代码检查/本地只读核验/方案整理，没有清库、导入、发送真实群消息或部署。

## 已有证据

- 最近一轮全量npm test通过，末尾前端子套件59项通过；Lint、生产构建通过。这里复核的是已有执行记录，本轮未无变化地重复整套测试。
- 之前已隔离验证实时权限、审核与公告送达、受控补发、维护窗口、备份/回滚；Excel实际下载与精简PDF已浏览器验证。真实企微和正式反向代理验收仍不能以隔离测试代替。
- 本轮以Node24内置SQLite只读打开workspace data/standards.db，不调用initDB：quick_check=ok，foreign_key_check=0。
- 本地标准主记录879、版本879、变更2060、批注关联1327、导入来源115、催审状态2、outbox0；最新状态806已发布、2待审、71停用。这是本地观察，不是新Excel应有数量，也不代表另一测试/正式环境的实时数据。

## 必须解决的三项

1. 新Excel作为唯一上线基线：提交原件后检查全部sheet/分类、近期新增、规格和批注、作废与待定项；目前未提供，无法判断新版数据是否完整。
2. 现有初始化导入为追加/跳过重复，并不全量替换；卫浴脚本绑定旧hash和固定45条，不能用于新文件。需要专用、可预览/归档/回滚的基线替换入口与演练。
3. 正式版本和环境：大量新模块仍是工作区未跟踪文件，需在获准提交时完整纳入发布版本。部署前核对实际服务器配置、数据路径、正式群和用户绑定；代码部署和数据替换分别授权。

## 数据处置口径

旧标准、历史、批注、待审/催审、公告任务不带入新正式库，先离线归档再移出在线库；账号、权限和其他模块数据不自动清理。最近新建的真实标准须并入新Excel，或在差异清单中明确决定。初始化不群发、不伪造审核记录；启用真实催审前检查绑定与待审状态。
